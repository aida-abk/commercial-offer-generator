# Деплой на Railway

Приложению нужен обычный «всегда включённый» сервер: внутри работает Chrome
(рендер листов проекта и генерация PDF), база лежит файлом SQLite, а разбор
проекта длится минутами. Поэтому — Docker-контейнер с постоянным диском, а не
serverless.

## Что понадобится

- Аккаунт Railway и репозиторий на GitHub (уже подключён: `aida-abk/commercial-offer-generator`)
- Ключ `OPENAI_API_KEY`
- Пароль для входа `APP_PASSWORD`

## Шаги

1. **Создать проект.** Railway → New Project → Deploy from GitHub repo → выбрать
   репозиторий. Dockerfile в корне подхватывается автоматически, отдельная
   настройка сборки не нужна.

2. **Подключить диск.** Том создаётся не в настройках сервиса, а с холста
   проекта: **⌘K → Volume** или правый клик по пустому месту холста. Точка
   монтирования — **`/data`**. Без тома история КП и правки прайса пропадают
   при каждом деплое.

   Проверить, что всё срослось, можно по `/<адрес>/api/health`: поля
   `data.mounted` и `database.onVolume` должны быть `true`, а в `warnings`
   должно быть пусто. Если `onVolume: false` — база лежит внутри контейнера
   и исчезнет при следующем деплое.

3. **Задать переменные.** Service → Variables:

   | Переменная | Значение |
   |---|---|
   | `OPENAI_API_KEY` | ваш ключ OpenAI |
   | `APP_PASSWORD` | пароль входа (общий для всех сотрудников) |
   | `DATA_DIR` | `/data` |
   | `DATABASE_URL` | `file:/data/offers.db` — обязательно абсолютный путь внутри тома |
   | `OPENAI_PAGES_PER_REQUEST` | `3` (при тарифе OpenAI 10 000 TPM) |
   | `OPENAI_TPM_BUDGET` | `9000` |

   `PORT` Railway подставляет сам, задавать его не нужно.

4. **Открыть доступ.** Service → Settings → Networking → Generate Domain.
   Railway выдаёт HTTPS-адрес — это обязательно: кука сессии помечена `secure`,
   по обычному `http` войти не получится.

5. **Проверить.** Открыть выданный адрес, войти по паролю, сформировать КП
   вручную (без PDF) — это проверяет базу и расчёт. Затем загрузить настоящий
   проект — это проверяет Chrome и OpenAI.

## После первого запуска

- **Бэкап базы.** Все КП лежат в одном файле `/data/offers.db`. Railway →
  Volumes позволяет скачать содержимое; делайте это перед крупными обновлениями.
- **Смена пароля** — в переменной `APP_PASSWORD`. Меняется для всех сразу,
  у всех слетают сессии.
- **Цены** правятся через `/admin` и сохраняются в `/data/price-catalog.json`,
  то есть переживают деплой. Файл `config/price-catalog.json` в репозитории —
  только эталон для первого запуска.

## Если сайт «не работает»

Откройте `/<адрес>/api/health` — он отвечает без пароля:

- `startedAgo` маленький — сервис недавно перезапускался (сбой или деплой)
- `memory.limitMb` близко к `usedMb` — не хватает памяти, контейнер убивают
- `warnings` не пустой — проблема с хранением данных

Ещё одна частая причина — режим **Serverless** в настройках сервиса: он
усыпляет контейнер через 5–10 минут простоя, и первый запрос после сна ждёт
запуска. Для этого образа пробуждение занимает десятки секунд и выглядит как
зависший сайт. Для рабочего инструмента его лучше выключить.

## Известные ограничения

- **Лимит OpenAI.** При тарифе 10 000 токенов/мин разбор одного проекта идёт
  2–4 минуты, а два одновременных разбора конкурируют за лимит: часть листов
  может не распознаться (это попадёт в заметки к КП). Если поднять тариф
  OpenAI, поставьте `OPENAI_PAGES_PER_REQUEST=10` и `OPENAI_TPM_BUDGET=30000` —
  разбор ускорится примерно до полуминуты.
- **Один общий пароль.** Отдельных учёток у сотрудников нет, и в истории не
  видно, кто создал КП.
- **Тяжёлый репозиторий.** В git лежат примеры проектов (~470 МБ), из-за чего
  каждый деплой дольше клонирует исходники. В образ они не попадают
  (см. `.dockerignore`). Новые PDF в репозиторий лучше не добавлять.

## Локальная проверка образа

```bash
docker compose up -d --build
```

Поднимет то же самое на `http://localhost:3000` с томом `kp-data`.
Переменные берутся из `.env`.
